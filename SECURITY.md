# Security

## Current Repository Review Boundary

Repository analysis accepts an explicitly chosen local directory or a token-free public GitHub repository. Source is untrusted data: no workflows, scripts, package hooks, IaC evaluator, Git helper or target dependencies are executed by the analyzer. Fixed acquisition/file/parser limits reject or report incomplete inputs; links and Windows reparse points are not followed. Local inputs include present files rather than applying arbitrary `.gitignore` rules.

The first source profile is intentionally narrow. It proves only a path in supported declarations under assumed job compromise, never actual compromise, exploitability, effective deployed permissions or secret existence. Unknown restrictions must not become allows. Job principals are isolated; role account/path correlation and unresolved denies/conditions/boundaries/managed policies have dedicated regression tests. Other deployment policies, SCPs, resource policies, runtime controls and conditions can still change deployed access. No findings is not a safety verdict. Counterfactual removal is in memory, not an applied edit or guaranteed production fix.

Finite literal matrix expansion is bounded to 64 variants per matrix, 256 expanded job variants and 512 identity requests per workflow. Different matrix variants have separate principal IDs. Only direct matrix references and literal env values in explicit workflow/job/step scopes can be substituted; dynamic or shadowing expressions are not evaluated, and unresolved child values cannot inherit a resolved parent accidentally. Resolved role/audience facts carry supporting source locations. This is declared static context, not proof of runtime values: arbitrary `$GITHUB_ENV` writes, action behavior and runner state are not evaluated.

Unresolved role references record their context/name and job/source coordinates, not a secret value. Locally referenced actions with a role input are retained as unverified observations, never converted into AWS credential-exchange facts. Unsupported credential options remain blockers. Matrix fields named like passwords, tokens or credentials are redacted before output; other literal matrix values are source metadata and may still be sensitive. This is not automatic secret detection or anonymization. Do not send credential values to satisfy an evidence request.

Conventional CloudFormation JSON/YAML files can be composed without constructing Python objects. Known intrinsic tags (`!Ref`, `!Sub`, etc.) remain opaque to all literal-value helpers, with diagnostic source locations; no evaluator runs. Only independent literal declarations may contribute paths. Arbitrary custom tags, aliases, duplicate keys, merge keys and resource limits remain enforced. A parsed template is not a fully evaluated deployment.

### Local Browser Service

`blastradius review` binds only `127.0.0.1`. It requires the exact host, same origin and an unpredictable per-process request token for API operations. It rejects CORS/preflight, DNS-rebinding hostnames, duplicate/oversized bodies and unsupported routes. Responses are no-store and non-frameable; script/style hashes and embedded assets avoid remote UI dependencies. The server serves no arbitrary filesystem path, does not echo absolute source roots, never persists user paths in browser storage, and does not log request contents. One operation runs at a time. Only the latest result is retained in memory and it can be cleared.

The live investigation keeps one baseline graph and its parsed evidence facts in memory, not the raw source directory. Public temporary archives are still deleted after acquisition; simulation does not reopen or redownload source. `/api/simulate` and `/api/export-plan` use the same origin/host/token/operation lock as analysis and reject stale baseline hashes, unknown controls, duplicates and more than 128 selected statements. Simulations remove selected controls from a copied graph and rerun the engine across its jobs; they do not apply source or infrastructure changes. Clear/new analysis replaces the retained context. Source conditions and statement metadata may disclose architecture even without secret values.

This is a single-user workstation service, not an authenticated multiuser platform or a sandbox against hostile local processes. Do not expose it through proxies, port forwarding or public interfaces. Do not run with elevated privileges. A local process with the user's privileges can access the service and filesystem; browser isolation is not host isolation. Parsing/analysis still consumes finite local memory/CPU, and this is not a hardened public ingress or an OS-enforced analysis sandbox.

HTML/SARIF/Markdown reports neutralize source-derived text; generated HTML embeds no session token and makes no network request. Public source links point at the resolved immutable GitHub commit only. Downloads may disclose repository identifiers, ARNs, paths and declared trust relationships. They are not anonymized, encrypted or authenticated. The result SHA-256 checks content consistency, not authorship: someone who can modify a result can recompute it. Treat imported/downloaded reports and artifact permissions accordingly. Secret values are not part of the result model.

### CI Trust Boundary

The included `pull_request_target` workflow obtains analyzer/workflow code from the trusted base revision and only then checks out the PR revision as data. The review job has read-only repository permissions, no persisted Git credentials, no cloud credentials, no secrets, no dependency cache and no target code execution. Python runs with `-I` outside the target directory; a regression plants target `sitecustomize.py`, `json.py`, `yaml.py` and a shadow package and asserts none execute. All actions are pinned to full commit hashes. This does not make changing the workflow casually safe: never install or execute the target revision from this privileged event context.

Four review artifacts and a provenance/checksum manifest are uploaded to the repository's GitHub Actions storage for seven days. No raw repository source is sent to an analysis service. Repository/fork visibility still governs access to these structural reports; disable artifact publication if that visibility is inappropriate. SARIF publication has separate write permission only in an explicitly requested manual run. Hosted execution and fork-specific publishing have not been verified in this session. The pre-existing standard-verification workflow runs normal repository tests in its own unprivileged PR context; it is not the repository-review analyzer and was not changed.

## Historical Synthetic Research Boundary

The earlier research commands permit synthetic graph data only. Fictional markers are a use contract, not proof that a relabeled input is harmless. Their credential nodes carry metadata, never credential values. This historical restriction does not prohibit the current explicit repository-source inputs above.

Local synthetic results are plaintext. HMAC-SHA256 signing uses an OS-random local key stored outside the project and excluded from checkpoints. Verifiers holding that key can also forge results: this is local tamper detection, not public attestation or protection against a compromised host. Production signing-key custody, encrypted tenant persistence and private disclosure channels require review before any real tenant workflow.

Keep generated keys private. Never store keys in fixtures, repositories, demo HTML, OneDrive artifacts or report bodies. Signed reports disclose synthetic graph structure intentionally. Real tenant input is not supported. The future read-only transport is testable offline and is not a production collection claim.

No dedicated vulnerability-reporting address has been established. Use a previously verified private maintainer channel for sensitive reports; do not post secrets in issues or chats.

Public conformance executes an operator-supplied command with the operator's privileges; it is not a sandbox. Fixture hashes, contained paths, timeouts and output checks protect evaluation integrity, not a host from malicious local programs. Run third-party adapters only in an appropriate isolated environment. The captured-output limit is checked after process execution, not a hard streaming memory cap.

Structural summaries are explicitly not anonymous. The discrete-noise aggregate experiment is synthetic-only, and its public seed provides no privacy for real input. A production release requires independent review, durable contribution/budget enforcement, secret randomness and neutral custody. No real upload endpoint or management service is implemented.
